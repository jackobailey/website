# Ward explorer

`/ward2024` is a standalone Astro page with a React/Leaflet explorer. It does not use the site's header, footer or global stylesheet. On desktop the map sits to the left of the vote-share chart; on small screens they stack. The default example is Astley Bridge. Search supports ward names, constituency names, regions and codes; selected wards have shareable URL fragments such as `/ward2024#E09000001`.

The page serves its own estimates, TopoJSON boundaries and fonts. No map tile service, API key or visitor geolocation is required. Map colours indicate the largest point estimate, including the combined Other category; they are not winning probabilities. Charts retain a fixed 0–100% scale and show the published 95% intervals. Missing zero-share party rows stay omitted.

Legend party labels are keyboard-accessible toggle buttons. Selecting one shades every ward by that party's point estimate on a fixed white-to-party-colour 0–100% square-root scale and changes tooltips to that party's share. Colour intensity is `sqrt(share)`, so 25% receives half intensity; this emphasises lower shares without rescaling separately by party. Legend ticks use the same transform but display actual percentages. Omitted party rows count as zero for map shading. Selecting the active party again or using “Show leading party” restores the categorical map. Switching mode preserves the selected ward, chart and map position; zoom, hover and subsequent ward selections retain the active shading.

Leaflet uses the shared, pre-simplified boundaries without further per-polygon simplification or clipping, and redraws directly at the new zoom level. Ward headings stay on one line and omit redundant parenthetical council qualifiers; census part labels remain. Long names use an ellipsis, with the full source name available on hover and to screen readers. The constituency label also stays on one line so selections do not move the chart.

Chart changes run in two stages: shares, percentage labels and intervals interpolate for 350 ms in the existing row positions, then rows move into vote-share order over 350 ms. New/absent parties grow from/shrink to zero before sorting. A new selection interrupts the old transition and starts from the displayed values and positions. Reduced-motion preferences skip both stages; the accessible table updates immediately to the selected ward.

## Data and geography

`public/data/ward2024/sources.json` records the pinned source revision, SHA-256 checksums, boundary source and transformations. All 47,376 published CSV rows match the browser estimates to their documented six-decimal precision. Exact ties are identified before rounding. All 7,993 census ward codes have unique, nonempty valid geometries.

Use the ONS **December 2022 BFC** shapefile, not an arbitrary 2024 boundary file. The preparation script dissolves City of London and Isles of Scilly to the two census areas, rekeys both Hunmanby & Sherburn parts by name, and excludes Northern Ireland. See the source project's boundary README for the BGC naming discrepancy. Polygons are simplified for display, so this map is unsuitable for exact boundary enquiries.

## Rebuild the static assets

Normal `npm run build` uses the checked-in assets and does not require R or network access. To refresh the source snapshot, download the CSV at a known GitHub commit and obtain the shapefile with its accompanying `.dbf`, `.shx` and `.prj` files, then run:

```sh
python3 scripts/build-ward2024.py \
  --csv /path/to/ward_ge2024_results.csv \
  --shapefile /path/to/WD_DEC_2022_UK_BFC.shp \
  --release-metadata /path/to/github-release.json \
  --revision <40-character-source-commit>
npm run build
```

Asset preparation requires R with `sf` and `dplyr`, plus the npm development dependency `mapshaper`. It checks source keys, finite shares and bounds, within-ward sums, exact boundary coverage and the validity of the final browser geometry. Revisit the explicit 7,993-ward assertion when intentionally changing the geography. Recheck the source method text and download link whenever publishing a new data release.

The optional release metadata is the saved response from GitHub's releases API. The builder verifies the CSV asset's SHA-256 digest before using its versioned download URL. This preserves the source project's release download counter and ensures downloads match the mapped snapshot; without it, the link uses the pinned raw CSV.

Browser verification should cover map clicks, search by name/code, keyboard arrows/Enter/Escape, zoom/reset, the method dialog, direct-link reloads, census exceptions, Scotland/Wales, narrow mobile screens, and the production build. Model validity and independent ward-level accuracy are outside these interface/data-transfer checks.
